# LEX

LEX помогает сотруднику находить ответы в корпусе внутренних регламентов. Он
сопоставляет вопрос с документами, учитывает дату и доступ пользователя,
показывает подтверждающие фрагменты и объясняет отказ, если надёжного ответа
нет. Для неразрешённых вопросов предусмотрен переход к заявке в службу качества.

Проект включает Python API на FastAPI, поисковое ядро, локальные сервисы
эмбеддингов и ранжирования, а также веб-интерфейс. Текущий статус и подробные
границы реализации описаны в [`docs/LIMITS.md`](docs/LIMITS.md).

## Быстрый старт: 5 команд

Команды рассчитаны на Windows и запускаются в Git Bash из корня репозитория.
Нужен Python 3.12 или новее.

```powershell
# 1. Создать изолированное окружение Python
python -m venv .venv

# 2. Установить минимальные зависимости API
./.venv/Scripts/python.exe -m pip install fastapi uvicorn numpy httpx python-dotenv pydantic

# 3. Создать небольшой синтетический корпус для проверки
./.venv/Scripts/python.exe demo/gen-sample-corpus.py --out var/quickstart-corpus --count 20 --seed 20261126

# 4. Выполнить лексический прогон без вызова LLM
bash demo/run-local.sh --skip-preflight --keep --out var/quickstart-corpus --run-out var/quickstart-run

# 5. Запустить HTTP API на локальном компьютере
./.venv/Scripts/python.exe -m uvicorn src.api.app:app --host 127.0.0.1 --port 8874
```

После запуска API откройте `http://127.0.0.1:8874/api/docs`. Команда 4 проверяет
только поиск по синтетическому корпусу и не обращается к языковой модели.
Для полноценной работы задайте переменные подключения из `docs/MODEL.md` и
запустите локальные сервисы эмбеддингов и ранжирования по инструкциям в
`scripts/`.

В репозитории пока нет lock-файла Python-зависимостей; команда 2 устанавливает
минимальный набор для старта API, но не фиксирует версии.

## Модель и данные

- Генерация ответа идёт через NexusLink на `sage-pl`; это внешний по отношению
  к LEX сервис маршрутизации моделей.
- Эмбеддинги создаёт локальный `bge-m3`, ранжирование кандидатов выполняет
  локальный `bge-reranker-base`.
- Локальная языковая модель не используется. Переменные адреса и токена
  задаются в окружении; секреты не хранятся в репозитории.
- Примеры в `sample-corpus/` синтетические и не заменяют данные заказчика.

## Что переиспользовано из NEXUS

Ранее созданный NexusLink используется как HTTP-сервис для маршрутизации LLM.
Исходный код шлюза лицензирован Apache-2.0, но не включён в этот репозиторий и
не распространяется вместе с LEX. Код интеграции написан в LEX и покрывается
лицензией этого репозитория — MIT.

Для поиска используются готовые веса `bge-m3` и `bge-reranker-base`; обе
официальные карточки моделей указывают лицензию MIT:
[bge-m3](https://huggingface.co/BAAI/bge-m3) и
[bge-reranker-base](https://huggingface.co/BAAI/bge-reranker-base). Это
модельные компоненты, а не скопированный код NEXUS.

Из прежних решений NEXUS перенесены только общие архитектурные подходы к
маршрутизации модели, фиксации этапов обработки и показу источников. Исходные
файлы и графические ресурсы NEXUS в проект не копировались. Код LEX и его
документация лицензированы по [`LICENSE`](LICENSE) (MIT).

## Ограничения

- Ответ зависит от доступности NexusLink и выбранного через него провайдера.
- Локальные сервисы `bge-m3` и `bge-reranker-base` должны быть запущены отдельно;
  их веса загружаются отдельно от исходников.
- Корпус для демонстрации синтетический. Качество на реальных документах
  заказчика отдельно не подтверждено.
- OCR сканов, единый вход пользователей и подключение к корпоративным системам
  пока не входят в подтверждённую реализацию.
- Python-зависимости пока не закреплены lock-файлом.
