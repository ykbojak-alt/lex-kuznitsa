# LEX

Ассистент, который отвечает сотруднику **только по регламентам организации**.
Не из интернета и не из памяти модели: каждое утверждение ответа подтверждается
цитатой из документа. Если ответа в базе нет — LEX не выдумывает, а задаёт
уточняющий вопрос или передаёт вопрос людям в службу качества. Ответ людей
возвращается в базу как кейс, и с этого момента тот же вопрос закрывается по
практике.

Компоненты: HTTP API на FastAPI, поисковое ядро (BM25 + вектор +
переранжирование), локальные сервисы эмбеддингов и ранжирования, веб-интерфейс.
Генерацию ответа выполняет модель через NexusLink — внешний по отношению к LEX
шлюз маршрутизации.

Стенд: `https://2.27.5.234.nip.io:4437`. Живой, корпус — 4 регламента заказчика,
все адреса `example.invalid`, письма имитируются.

## Три критерия приёмки

| Критерий | Как выполняется | Где проверяется |
|---|---|---|
| **1. Ответы строго по регламентам; нет ответа → запрос в службу качества.** Недостоверный ответ = не точно по регламенту или дополненный внешними знаниями | Три барьера: системный промпт запрещает использовать что-либо кроме переданных фрагментов; утверждение без дословной цитаты выбрасывается; гейт релевантности (покрытие предмета ≥ 0.75, близость ≥ 0.50) отсекает вопросы, которых в корпусе нет | `src/lex/orchestrator.py:101`, `src/lex/grounding.py:41`, `src/api/stats.py:29-30` |
| **2. Уточняющий диалог при неоднозначности** | 2–3 итерации уточнения, затем эскалация; уточнение не тратит модель | `src/lex/dialogue.py:52-53` |
| **3. Дообучение через службу качества** | Заявка → ответ человека → кейс в базе → тот же вопрос отвечается уже по кейсу с пометкой «по практике, регламент не покрывает» | `src/lex/orchestrator.py`, `_stage_cases` |

Подробный разбор — [`docs/LEX-ONE-PAGER.md`](docs/LEX-ONE-PAGER.md), честные
границы — [`docs/LEX-LIMITS.md`](docs/LEX-LIMITS.md), риски показа —
[`docs/LEX-RISKS-DEFENSE.md`](docs/LEX-RISKS-DEFENSE.md).

## Запуск локально

Нужен Python 3.11 или новее (`pyproject.toml`). Команды — для Git Bash из корня
репозитория.

```bash
# 1. Окружение
python -m venv .venv

# 2. Зависимости HTTP-слоя
./.venv/Scripts/python.exe -m pip install fastapi uvicorn numpy httpx python-dotenv pydantic

# 3. Секреты и адреса — в .env, не в коде
cp .env.example .env      # затем заполнить NEXUSLINK_KEY и NEXUS_LINK_BASE_URL

# 4. Локальные сервисы поиска (отдельные окна, грузят веса 5–20 с)
pwsh -File scripts/start-embed.ps1      # :8081, bge-m3
pwsh -File scripts/start-rerank.ps1     # :8082, bge-reranker-base

# 5. Собрать UI и поднять API
bash scripts/build-web.sh
./.venv/Scripts/python.exe -m uvicorn src.api.app:app --host 127.0.0.1 --port 8874
```

Дальше: `http://127.0.0.1:8874` — интерфейс, `http://127.0.0.1:8874/api/docs` —
схема API. Проверка готовности: `curl -s http://127.0.0.1:8874/api/health`.

Локальные сервисы эмбеддингов и ранжирования требуют Python 3.12+ и
`sentence-transformers`; скрипты сами ищут интерпретатор (переопределяется
переменной `LEX_PYTHON`). Если они не запущены, поиск честно деградирует до
BM25 — каскад не падает, но точность ниже.

### Прогон без модели

Лексический прогон (проверяет конвейер и качество поиска, не вызывает
`chat/completions`):

```bash
bash demo/run-local.sh --skip-preflight --keep --run-out var/eval
```

На чистом окружении с нуля корпус можно сгенерировать:
`demo/gen-sample-corpus.py --out var/quickstart-corpus --count 20 --seed 20261126 --clean`.

## Запуск на сервере

```bash
./deploy/deploy-sagepl.sh root@<хост> /opt/lex-kuznitsa
```

Скрипт копирует код (`src/`, `demo/`, `scripts/`, `schema/`, `deploy/`, `docs/`,
`sample-corpus/`), создаёт venv, ставит зависимости, ставит и запускает
`lex-stand.service`, затем проверяет `curl -sf http://127.0.0.1:8090/api/health`.

**Не копируется никогда:** `dataset/`, `corpus-real/`, `sample-corpus-real/` —
документы заказчика не уходят на чужую машину; `.env` — секреты, на стенде свой
файл; `var/` — рабочие записи. Эти же каталоги в `.gitignore`: репозиторий
публичный.

Стенд слушает `127.0.0.1:8090`, наружу не выставлен — доступ через ssh-туннель
или реверс-прокси хостера. Подробности и откат — [`deploy/README.md`](deploy/README.md).

**Память.** Две локальные модели (`bge-m3` + `bge-reranker-base`) в пике
занимают около 3 ГиБ; на хосте с 4 ГБ RAM нужен swap не меньше 4 ГБ, иначе
ядро убивает сервис посреди запроса. Требования и замеры —
[`docs/DEPLOY-RESOURCES.md`](docs/DEPLOY-RESOURCES.md).

## Модель и корпус

**Модель.** Генерация — через NexusLink на `sage-pl`. Эмбеддинги — локальный
`bge-m3` (1024), переранжирование — локальный `bge-reranker-base`. Локальная
языковая модель не используется. Параметры: `NEXUS_LINK_BASE_URL`,
`NEXUS_LINK_MODEL`, `NEXUSLINK_KEY`, `LEX_EMBED_URL`, `LEX_RERANK_URL`; ключи
только в `.env`.

**Какой корпус читать.** Корпус выбирается переменной `LEX_CORPUS_DIR`; по
умолчанию читается `corpus-real/` — регламенты заказчика (`src/api/config.py:21`).

```bash
# по умолчанию — регламенты заказчика
python -m uvicorn src.api.app:app --port 8874

# синтетика для тестов и работы без данных третьей стороны
LEX_CORPUS_DIR=sample-corpus python -m uvicorn src.api.app:app --port 8874
```

`sample-corpus/` — 27 синтетических документов и 3 правила редакций, для
проверки и разработки. В `corpus-real/` правил редакций нет, поэтому каскад
пропускает шаги `resolve` и `conflict` — 9 шагов вместо 11
(`src/lex/orchestrator.py:392-403`).

**Права.** Чтение фильтруется по отделу с v1.16 (режим `department_read`); роли
выводятся из манифеста: `technical` (Техническая дирекция), `ib` (Дирекция ИБ),
`dbrct` (ДБРЦТ), `quality` (Служба качества), `director` (Руководитель).
Запись — `quality` и `director`. Сколько документов видит каждая роль —
`GET /api/roles`.

## Что переиспользовано из NEXUS

NexusLink используется как внешний HTTP-сервис маршрутизации LLM: исходный код
шлюза лицензирован Apache-2.0, но в этот репозиторий не включён. Код интеграции
написан в LEX и покрыт лицензией репозитория — MIT.

Веса `bge-m3` и `bge-reranker-base` — официальные модели под MIT
([bge-m3](https://huggingface.co/BAAI/bge-m3),
[bge-reranker-base](https://huggingface.co/BAAI/bge-reranker-base)). Из прежних
решений NEXUS перенесены только общие архитектурные подходы; исходные файлы и
графические ресурсы не копировались. Лицензия — [`LICENSE`](LICENSE) (MIT).

## Ограничения

Коротко (полный разбор — [`docs/LEX-LIMITS.md`](docs/LEX-LIMITS.md)):

- **Ответ зависит от внешнего NexusLink.** Задержка не под контролем LEX:
  медиана 29 с, худший случай 41 с (замер 27.11). Разброс большой, потому что
  цепочка слотов пробует несколько моделей — от ~6 до ~30 с в зависимости от
  того, какая ответила.
- **Корпус — только выданные документы.** Нет документа — нет ответа; это
  критерий приёмки, а не дефект.
- **~25 % вопросов уходят в уточнение** — четыре регламента покрывают узкую
  тему.
- **Один вызов модели на большинство вопросов** (1–4 на сложных), без
  агентного поиска.
- **OCR недоступен**: сканы не читаются, корпус — markdown. Если регламенты
  лежат сканами, их надо распознать до загрузки.
- **Конфликт редакций показывать нечего**: в `corpus-real` 0 правил.
- Python-зависимости не закреплены lock-файлом: команда установки в «Быстром
  старте» не фиксирует версии.
