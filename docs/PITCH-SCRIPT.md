## 1. Закрывашка / проблема (0:00–0:30)

> «Сотрудники тратят время на поиск ответов в регламентах, инструкциях и корпоративных документах. Ошибка — это не просто потерянное время: это риск нарушения процедуры. Мы сделали RAG-агента, который отвечает по корпоративным документам, показывает источники и честно отказывается, когда ответа в корпусе нет. Основной путь inference — Nexus Link (sage-pl), локальная модель — fallback».

**На экране:** название, 1 строка проблемы, пометка "Nexus Link (sage-pl) — основной; локальный fallback" (если подтверждено).

## 2. Решение и демо (0:30–2:00)

### Что показываем
1. **Вопрос по документу** — агент находит релевантные фрагменты и даёт ответ с цитатой/источником.
2. **Вопрос с конфликтом/отсутствием** — агент не выдумывает, а возвращает отказ или указывает конфликт.
3. **Журнал** — видно, что было найдено, какой источник использован.

### Что говорим
> «Мы индексируем корпус, ищем релевантные фрагменты, передаём их в Nexus Link (sage-pl) как основной путь генерации и требуем ответ с опорой на источник. Локальная модель Qwen3-8B-Instruct Q4_K_M на RTX 3050 8 GB — fallback на случай недоступности основного контура. Если источник не найден или данные конфликтуют, агент отказывается, а не галлюцинирует».

**На экране:** запрос → найденные чанки → ответ → источник. Без заранее заготовленных "идеальных" скриншотов.

## 4. Экономика и границы (3:30–4:30)

### Экономика (честно)
- **API токены / стоимость inference:** основной путь — Nexus Link (sage-pl), стоимость считать по контуру/использованию; локальный fallback — без платы за внешние токены API (если подтверждено отсутствие внешних вызовов).
- **Железо:** ориентир — рабочая станция с RTX 3050 8GB для демо; для пилота считать отдельно.
- **Внедрение:** зависит от корпуса, прав доступа, форматов документов, интеграций.

### Границы
- Маленький демо-корпус ≠ продакшн качество.
- Ручная разметка мини-датасета субъективна.
- RAG снижает галлюцинации, но не устраняет их полностью; нужен аудит/верификация.
- Контроль доступа и интеграции с корпоративными системами — следующий этап, не "уже готово".

## Q&A — заранее подготовленные ответы

- **Почему Nexus Link как основной, а локально — fallback?** Nexus Link (sage-pl) даёт единый управляемый контур inference; локальная модель Qwen3-8B остаётся fallback на случай недоступности/ограничений и для изолированного режима. Вопрос передачи данных и изоляции подтверждаем на брифинге.
- **Как боретесь с галлюцинациями?** Retrieval + ответ только по найденным фрагментам + цитаты + отказ при низкой уверенности/отсутствии источника.
- **Что если документов много?** Нужны нормальный чанкинг, гибридный поиск, реранкер, обновление индекса; это часть пилота.
- **Что уже есть, а что нет?** Есть: RAG-срез с Nexus Link как основным путём и локальным fallback, docs/методика/план. Нет: продакшн RBAC, интеграции, большой размеченный датасет.
