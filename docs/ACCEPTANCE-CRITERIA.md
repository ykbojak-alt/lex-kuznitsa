# ACCEPTANCE-CRITERIA.md — критерии приёмки продукта перед сдачей жюри

Статус: предспринтовый чек-лист. Финальная отметка ставится перед сдачей по факту прогона.
Требования к видео (§3.0) дополнены 27.11.2026 из Положения организатора.

## 1. Продукт / поведение

> **Две разные нумерации шагов — не путать.** «7 шагов пайплайна» в P1 — это
> **смысловые этапы** продукта (приём → … → логирование). В интерфейсе LEX шаги
> идут по `STEP_ORDER` (`src/lex/models.py:34`): **11 стадий**, из которых на
> корпусе без `conflict_rules` пропускаются `resolve` и `conflict`, и в кадре
> видно **9 шагов `[1/9]…[9/9]`**. Титр счётчика и текст «7 шагов» — про разное.

| ID | Критерий | Как проверяем | Статус |
|---|---|---|---|
| P1 | **7 шагов пайплайна работают end-to-end** | Прогон демо-сценария фиксирует все шаги: приём запроса → разбор/уточнение → retrieval → ранжирование/отбор контекста → генерация ответа → проверка/цитирование → логирование/выдача. Каждый шаг виден в логе/trace. | [ ] |
| P2 | **Обоснованный отказ** | На вопросах вне корпуса/без достаточного основания агент возвращает честный отказ или пометку недостаточности данных, не галлюцинирует факт. Проверяется минимум 3 кейсами из eval-набора типа "нет в корпусе". | [ ] |
| P3 | **Действующий документ / актуальность** | При конфликте версий/статусов документов агент указывает действующий документ или явно маркирует конфликт; источник ответа содержит идентификатор/дату/версию документа. | [ ] |
| P4 | **Аналитика журнала** | Журнал запросов/ответов позволяет получить базовую аналитику: количество запросов, доля отказов, средняя/ p95 latency, top источников/типов вопросов (минимальный набор метрик согласован). | [ ] |
| P5 | **Основной/ fallback inference** | Основной путь — Nexus Link (sage-pl). Локальная модель Qwen3-8B — fallback. Переключение/режим задокументирован и воспроизводим. | [ ] |
| P6 | **Воспроизводимый локальный запуск** | Демо поднимается по `demo/README.md` на чистом окружении (или оговорённом стенде) без ручной магии. | [ ] |

## 3. Видео

### 3.0. Требования организатора к самой форме сдачи (Положение, 27.11.2026)

Поле «Демо-видео» в заявке — **обязательное**. В него вставляют ссылку,
начинающуюся с `http://` или `https://`. **Видео должно открываться по ссылке
без запроса доступа** — если плеер просит вход, заявка не принимается.

| | Требование |
|---|---|
| 🟢 Надо | продолжительность **до 3 минут** (не «3–4», см. V1 ниже); запись **одним фрагментом, без монтажа**; на видео показана **работа продукта на данных задачи**; видео отражает **фактическую работу продукта** — направляя продукт, это подтверждается |
| 🟢 Можно | ускорять фрагменты ожидания ответа модели; субтитры, подписи, стрелки-пояснения; голосовой комментарий; окно с камерой в углу; запись не во весь экран, а окна приложения или нужной области |
| 🔴 Нельзя | склейки, нарезку и **любой монтаж** — видео должно быть одним фрагментом; длиннее 3 минут; заменять показ работы презентацией или слайдами; показывать функциональность, которой в продукте нет |

**Следствие для нашего материала.** Не успели что-то — пишется в описании в
графе нереализованной функциональности (`docs/LIMITS.md`, `docs/ONE-PAGE.md`),
а не показывается в кадре. Ускорение ожидания — единственная допустимая
правка времени; всё остальное, что меняет кадр, — монтаж.

## 4. Gate перед сдачей

Сдача разрешена только если:
- все P1–P4 подтверждены фактическим прогоном;
- R1–R8 присутствуют в репозитории и актуальны;
- V0–V8 выполнены, либо отклонения явно описаны в `docs/LIMITS.md` / отчёте сдачи;
- в материалах нет секретов, приватных ключей, персональных данных и необоснованных заявлений.
