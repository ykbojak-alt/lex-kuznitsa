# PITCH-VIDEO.md — сценарий видео-питча LEX, 90 секунд

**Статус:** pre-sprint материал (2026-11-25). Код продукта не пишется до старта спринта.

**Что это.** 90-секундный видео-питч — отдельный артефакт рядом с демо-видео и устным
питчем. Задача — за полторы минуты показать: боль → продукт → доказательство → границы →
экономику. Его смотрят на входе (презентация/форма), до или вместо устного питча.

**Чем отличается от соседей:**

| Документ | Длительность | Формат | Задача |
|---|---|---|---|
| `docs/DEMO-SCRIPT.md` | ≤ 3:00 | непрерывный прогон | доказать, что агент работает |
| `docs/PITCH-SCRIPT.md` | 5:00 | устный, слайды | закрыть 6 критериев словами |
| **`docs/PITCH-VIDEO.md`** (этот) | **0:90** | монтажное видео | зацепить и объяснить за 90 с |

**Принцип.** Питч-видео **переиспользует** кадры демо-видео (не снимает заново) и
монтирует их плотно. Это монтаж, поэтому переходы разрешены — в отличие от тела
демо-видео. Голос — за кадром (записывается отдельно, кладётся на монтаж).

**Тайминг жёсткий:** 0:90 = 90 секунд. Блоки: вводка 20 с · демо 40 с · границы 15 с ·
экономика и следующий шаг 15 с. Резерв на дыхание — внутри блоков, не сверху.

---

## Технический формат

| Параметр | Значение |
|---|---|
| Разрешение | 1920×1080 (16:9) |
| Частота | 30 fps |
| Кодек | H.264 High, `yuv420p`, MP4 `+faststart` |
| Аудио | AAC 48 кГц, голос −16 LUFS, true-peak ≤ −1 dBTP |
| Длительность | ≤ 90 с (цель 88 с) |
| Размер | ≤ 60 МБ |
| Имя | `lex-pitch-<sha8>-<YYYYMMDD>.mp4` |

**Отличие от демо-видео:** здесь допустимы fade/dissolve между блоками — это осознанный
монтаж, а не выдача монтажа за живой прогон. Живые кадры внутри блока «демо» — из
реального прогона, без подмены ответов.

## Блок 1 — Вводка и проблема (0:00–0:20)

| | |
|---|---|
| **Таймкод** | 0:00–0:20 |
| **На экране** | 0:00–0:06 знак LEX (вводка из `DEMO-VIDEO-PROMPT.md`); 0:06–0:20 крупные титры-факты на графитовом фоне |
| **Голос (за кадром)** | «Сотрудник ищет ответ в регламентах — это не просто время. Это риск нарушить процедуру. Документы меняются редакциями, противоречат друг другу, и уверенный неверный ответ опаснее честного молчания. LEX — агент, который отвечает по корпоративным документам и умеет сказать «не знаю».» |
| **Титр на кадре** | 0:06: «Поиск ответа в регламентах» → 0:11: «Ошибка = нарушение процедуры» → 0:16: **«LEX — отвечает по документам и умеет сказать „не знаю"»** |
| **Монтаж** | знак → cut на титры; титры меняются каждые ~5 с, fade 8 кадров |

---

## Блок 2 — Демо (0:20–1:00)

Плотный монтаж **лучших кадров реального прогона** из демо-видео. Не переснимаем —
берём четыре ключевых фрагмента и режем между ними (монтаж допустим по природе питч-видео).

| Под-блок | Таймкод | Что на экране (из прогона) | Голос |
|---|---|---|---|
| 2a Разбор | 0:20–0:32 | панель шагов `[1/7]–[3/7]`, числа выдачи | «Вопрос разбирается на подвопросы. По каждому — гибридный поиск: точные термины плюс смысл, потом переранжирование.» |
| 2b Действующая редакция | 0:32–0:44 | три редакции SR-01, одна отброшена | «Вот ядро. Три редакции одного правила — агент берёт не самую новую, а действующую на дату вопроса.» |
| 2c Ответ с цитатой | 0:44–0:52 | ответ + источник + `[7/7] verify` | «Каждая фраза ответа привязана к цитате с номером редакции. Специалист проверяет, а не верит.» |
| 2d Отказ | 0:52–1:00 | структурированный отказ | «А когда ответа нет — не выдумывает. Объясняет причину, показывает, что нужно уточнить. Это штатный результат.» |

**Титр на кадре (постоянный, правый нижний угол):** `реальный прогон · локальная модель`
в течение всего блока 2 — маркер честности.

**Монтаж:** cut между 2a–2d, на каждом стыке — микро-fade 4 кадра, чтобы не «дёргалось».
Длительность 40 с — самый плотный блок; подрезать реплики, не кадры-доказательства
(2b и 2d не трогать).

## Блок 3 — Границы, честно (1:00–1:15)

| | |
|---|---|
| **Таймкод** | 1:00–1:15 |
| **На экране** | спокойный экран с двумя колонками: «Готово» / «Не готово» (титры, не видео) |
| **Голос** | «Честно о границах: демо-корпус синтетический, качество на документах заказчика не проверено, интеграций с корпоративными системами пока нет. RAG снижает выдумки, но не убирает их полностью — нужен аудит.» |
| **Титр на кадре** | «Готово: воспроизводимый срез, отказ, аналитика» / «Не готово: продакшн-RBAC, интеграции, большой датасет» |
| **Монтаж** | одна статичная плашка 15 с, лёгкая анимация появления колонок |

**Зачем этот блок в питче:** жюри ценит честность выше громких обещаний. Прямое
признание границ закрывает критерий «готовность» лучше, чем заявление «всё готово».

| | |
|---|---|
| **Таймкод** | 1:15–1:30 |
| **На экране** | таблица стоимости + три шага пилота + CTA |
| **Голос** | «Экономика: основной путь — управляемый шлюз, локальная модель — fallback без платы за внешние токены. Стоимость считаем по факту прогона, не по обещаниям. Следующий шаг — пилот на корпусе заказчика: контур, права, журнал, метрики.» |

| **Монтаж** | таблица fade-in, шаги появляются по одному, финальная плашка держится до 1:30 |

## Что закрывает каждый блок (6 критериев)

| Критерий (0–3) | Блок |
|---|---|
| Соответствие задаче партнёра | 1 (проблема), 2b/2d (действующий документ + отказ) |
| Корректность реализации | 2a–2c (реальный прогон, цитаты, самопроверка) |
| Потенциал внедрения | 4 (три шага пилота) |
| Готовность | 2 (работает) + 3 (честные границы) |
| Агентность | 2a (счётчик `[N/7]`, многошаговый цикл) |
| Экономика эксплуатации | 4 (стоимость по факту) |

Все шесть критериев покрыты за 90 секунд — это цель питч-видео. Глубину даёт демо-видео
и устный питч.

---

## Запреты

1. **Не выдавать монтаж за непрерывный прогон.** В блоке 2 — маркер «реальный прогон»;
   склейки есть, и это нормально для питча, но кадры — настоящие.
2. **Не подменять ответы** на кадрах демо — берутся из реального прогона.
3. **Не обещать** «production-ready», «100% точность», «полная интеграция».
4. **Не ставить цифры экономии**, которых не было в прогоне.
5. Секреты, ключи, домашние пути — вне кадра (кадры демо уже очищены по `DEMO-SCRIPT.md`).

## Чек-лист перед рендером

- [ ] Кадры блока 2 взяты из финального демо-видео (тот же SHA прогона).
- [ ] Голос записан отдельно, −16 LUFS, без клиппинга.
- [ ] Длительность ≤ 90 с (измерить ffprobe).
- [ ] Каждый из 6 критериев присутствует хотя бы в одном блоке (см. таблицу выше).
- [ ] Маркер «реальный прогон» виден в блоке 2.
- [ ] Имя файла содержит SHA прогона.
- [ ] Прогон через `docs/VIDEO-CHECKLIST.md`.
