# Тема: Недостаточность данных: возврат заявки на доработку

## Суть
Класс процесса — «возврат заявки на доработку»: когда данных и документов для расчёта
не хватает, исполнитель возвращает заявку с перечнем вопросов. Возврат — штатный шаг
процесса, а не отказ: работа продолжается после уточнения.

Ответ берётся из документа-источника, не из этой статьи. Если источника с таким
классом в базе нет — агент обязан сказать, что ответа нет, а не собирать из статьи.

## Синонимы / как спрашивают
- «не хватает данных», «запрос на уточнение», «вернуть заявку»
- «достаточность данных для расчёта», «заявка ушла на доработку»
- «кто задаёт вопросы заказчику», «как запросить дополнительные материалы»
- «ждём ответа исполнителя», «статус жду ответа»

## Что искать в базе
- Класс документа: разделы проверки достаточности данных и возврата заявки.
- Артефакты: чек-лист валидации заявки, перечень вопросов, статус заявки, возвращённая
  заявка.
- Роли: архитектор, пресейл-архитектор, менеджер по продаже решений.
- Термины: доработка, недостаточно данных, чек-лист, вопросы, возврат.

## Где искать
- Класс документа: разделы «проверка достаточности данных» и «сбор информации».
- Поля/признаки: статус заявки, чек-лист, перечень замечаний, кто возвращает.
- Что считать источником истины: раздел о достаточности данных того регламента, где
  этот шаг стоит.
- Соседние шаги: подготовка расчёта трудозатрат, сбор информации.

## Чего в базе НЕТ
- Формы чек-листа валидации в базе нет: чек-лист упомянут как внешний рабочий инструмент.
- Правил эскалации при долгом ожидании ответа в базе нет.
- Перечня обязательных входных данных в одном месте нет — они распределены по разделам.

## Типичные ловушки
- «Данных недостаточно» и «проект нереализуем» — разные выводы: первый про доработку,
  второй про прекращение работы со сделкой.
- Чек-лист валидации в базе отсутствует, поэтому перечислить его пункты по базе нельзя —
  надо сказать, что источник вне базы.
- Возврат заявки сдвигает сроки работы: в одном из регламентов это прямо сказано.
- Запрос дополнительных данных может идти и от заказчика через продавца — маршрут
  вопросов описан в разделе.

## Пример вопроса
- Пользователь: «Что делать, если для расчёта не хватает данных от заказчика?»
- Ожидаемый ход поиска: найти класс проверки достаточности данных, прочитать порядок
  возврата, роли и артефакты.
- Ожидаемый вид ответа: порядок действий по найденному разделу с идентификатором
  документа; при отсутствии чек-листа — прямо указать, что он вне базы.

## Примеры в локальном корпусе
- КД-ПС-02 — разделы «5. Завершение подготовки пресейла» и «6. Сбор информации»;
  КД-ПД-03 — раздел «2. Проверка достаточности данных для подготовки расчёта трудозатрат»;
  КД-ПД-01 — раздел «3. Назначение архитектора пресейла» (локальный корпус заказчика, в
  публичный репозиторий не попадает; пример, заменяемый реальной базой).
