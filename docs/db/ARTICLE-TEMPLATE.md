# Шаблон статьи для агента (метазнание retrieval)

Статья — **не документ корпуса** и не юридический источник. Это краткая txt/md-справка, которая помогает агенту понять: **что искать, где искать, какие ловушки ожидать**.

Статьи используются до/вместе с retrieval: сначала сузить пространство поиска, потом цитировать только реальные документы из источника.

## Формат

```text
# Тема: <краткое название>

## Синонимы / как спрашивают
- ...
- ... (включая разговорные/ошибочные формулировки)

## Где искать
- Типы документов: <регламент/инструкция/порядок/чек-лист/редакция правила/...>
- Поля/признаки: <doc_kind, department, rule_key, title, sections, effective_at, ...>
- Ключевые документы/правила: <doc_id или rule_key>
- Что считать источником истины: <какой документ приоритетен при конфликте>

## Типичные ловушки
- ... (редакции, даты, похожие названия, разные подразделения, будущая дата вступления)
- ... (когда нельзя отвечать уверенно)

## Пример вопроса
- Пользователь: "..."
- Ожидаемый ход поиска: <какие поля/типы/правила проверить>
- Ожидаемый вид ответа: <краткий ответ + цитата/ID документа + дата/редакция>
```

## Правила написания

1. **Только проверяемые факты.** Любая ссылка на документ/редакцию/дату/значение должна проверяться по `sample-corpus/manifest.json` или реальному источнику.
2. **Не подменять документ.** Статья направляет поиск; ответ агент даёт по найденному документу.
3. **Явно писать ловушки.** Особенно: несколько редакций, future effective date, одинаковые названия в разных подразделениях, документы без rule_key.
4. **Писать поле поиска.** Для каждой темы указывать, какие поля/типы фильтровать в первую очередь.
5. **Коротко.** Одна статья — одна тема. 10-25 строк полезного содержания, без воды.

## Анти-пример

Плохо: «Срок согласования обычно три дня».  
Почему плохо: нет источника, нет редакции, нет даты, нет указания где искать.

Хорошо: «По SR-01 на as_of 2026-11-26 действует редакция Р2 (ТЗ-ЭКЗ-СР01-Р2, effective 2026-06-01): пять рабочих дней; Р3 (2027-01-01) ещё не вступила в силу».
