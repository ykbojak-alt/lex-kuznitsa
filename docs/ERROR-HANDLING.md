# ERROR-HANDLING — как LEX обрабатывает ошибки

**Статус:** документирует образования по пути инференса и то, как LEX в них ведёт себя.
Опирается на `docs/DEPLOY-NEXUSLINK.md` §4–5, `docs/ARCHITECTURE.md` §6,
`docs/EVAL-HARNESS.md` §4.3, `demo/demo_stand.py` (класс `LLMUnavailable`) и
`demo/run-local.sh`.

Для каждого образования три поля: **причина** (откуда пришла ошибка), **системный
ответ** (что возвращает стенд/агент) и **что показывает в интерфейсе**.

---

## 1. NexusLink 401 / timeout → fallback на локальную модель

- **Причина:** токен отклонён или не задан, сетевой таймаут/битый контур — по
  `docs/DEPLOY-NEXUSLINK.md` §4 (`401`/`403`, `000`).
- **Системный ответ:** переход на профиль `local` (Qwen3-8B на
  `LOCAL_MODEL_BASE_URL`); активный путь записывается в артефакт прогона
  (`stub-summary.json`, поле `inference_path` = `local-fallback`), по стандарту из
  `docs/DEPLOY-NEXUSLINK.md` §5.
- **UI:** индикатор пути переключается на `local-fallback`; в истории ответов
  ответ формируется локальной моделью. Если локальная модель тоже недоступна —
  путь инференса не определён, инференс невозможен (по §5: demo-обвязка продолжает
  работать без ответа).

## 2. Пустой corpus → обоснованный отказ

- **Причина:** retrieval вернул 0 чанков — в корпусе нет источника ответа (триггер
  №1,2,3 из `docs/ARCHITECTURE.md` §6).
- **Системный ответ:** формат отказа `docs/ARCHITECTURE.md` §6:
  «Не могу ответить однозначно. Причина: …» + «Что нужно от вас: …» — не «ошибка»
  и без подставленных значений.
- **UI:** блок «Отказ» с причиной (например, «документ не найден в корпусе»).

## 3. LLM не отвечает → фолбек на лексический поиск

- **Причина:** `LLMUnavailable` после fallback — пустой ответ или ошибка разбора
  (`demo/demo_stand.py`: класс `LLMUnavailable`, `chat_json` — 2 повтора, затем исключение;
  `main()`: «падаю в deterministic scripted-режим (fallback)»). Режим по
  `demo/run-local.sh` — «лексический поиск без LLM».
- **Системный ответ:** ответ формируется по результатам лексического поиска (точные
  термины/порядок документов) по корпусу — без подтасовки и без «думаю, что».
- **UI:** ответ показывается без маркера LLM, с пометкой, что выдача по поиску.

## 4. Цитата не найдена → Refuse

- **Причина:** верификация ответа не подтвердила цитаты в источниках
  (`docs/EVAL-HARNESS.md` §4.3: отказ с подставленным значением — не отказ).
- **Системный ответ:** отказ — без придуманных цитат и значений.
- **UI:** блок отказа («поиск не сработал» по формату `docs/DEMO-FIXTURES.md` Фикстура 4)
  + причина отказа.

---

**Общее правило:** образования не превращаются в фальшивые успехи — все пути ведут
либо к ответу, обоснованному цитатами, либо к отказу/поиску с причиной, и UI это показывает
одной и той же формой (блок «Отказ»/пометка пути), а не скрывая состояние.
