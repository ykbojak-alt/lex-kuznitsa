**Лицензии.** Наш код — **MIT** (`LICENSE`). Колонка «Лицензия» в таблицах ниже

## 1. То, что создается в спринте (новое, наш код — MIT)

| Компонент | Описание | Роль в архитектуре | Зависимости (внешние лицензии) |
|---|---|---|---|
| **Ingest-пipeline** | Парсинг/чанкинг корпуса, нормализация метаданных, BM25-индекс, векторный индекс, вызов reranker. | §3 (retrieve) и §7 (analytics). | rank-bm25 (MIT), FAISS (MIT), bge-m3 (Apache-2.0) |
| **Orchestrator (agentic loop)** | Декомпозиция → retrieve → judge_relevance → resolve_conflict → gather_evidence → compose → [refuse] → log. Tool-calls, бюджет шагов, журнал. | Главный цикл §5 (agentic). | LLM через NexusLink или локальную Qwen3-8B (Apache-2.0) |
| **Document hierarchy logic** | Уровни приоритета (приказ > политика > регламент > инструкция > продукт > FAQ), формализация `f(уровень, дата, редакция, отмены, область)`. | §4 (действующий документ). | нет |
| **Conflict detector** | Два действующих документа одного уровня → правило приоритета не решает → отказ. Дочитывание соседних чанков, иерархия. | §6 (обоснованный отказ). | нет |
| **Search analytics** | Агрегация по журналу: отказы, неудачные поиски, «чего нет в каталоге», топ вопросов, покрытие. | §7 (критерий «Соответствие задаче»). | нет |
| **UI «ход мысли»** | Экран с пошаговым прогрессом (1/7 … 7/7), цитаты под каждым шагом, кнопка «Отказаться». | Видео-демо + критерий агентности. | SL UI Library (см. SL UI лицензию) |
| **Мини-датасет** | Вопросы по корпусу с ручными эталонами: `{id, question, expected_answer, expected_sources, type}`. Обязательно «непокрытые». | §9 (метрики). | CC-BY-4.0 (наш контент, публикуется) |

лицензию. Ничто не переносится «как есть» — переиспользуется идея/паттерн, и
это раскрывается в описании продукта (правило «ранее созданные компоненты
перечислить отдельно»).
