# METRICS.md — методика оценки демо ИИкузницы

## Принцип

Контрольного размеченного набора на старте **нет**. Оценка на спринте — практическая, воспроизводимая на мини-датасете, с честной фиксацией ограничений. Цель — не "научная метрика SOTA", а проверяемое качество демо.

## Мини-датасет

Создаётся в часы 0–4 спринта.

| Параметр | Значение |
|---|---|
| Размер | 20–30 вопросов |
| Источник | `sample-corpus/` + подготовленные демо-документы |
| Формат | JSONL: `{id, question, expected_answer, expected_sources, type}` |
| Типы вопросов | факт (40%), извлечение (30%), отказ/нет в корпусе (15%), мульти-док (15%) |

### Правила разметки
- `expected_answer` — короткий эталонный ответ или ключевые факты.
- `expected_sources` — список файлов/фрагментов, которые должны быть найдены.
- Вопросы "нет в корпусе" должны получать честный отказ, не галлюцинацию.

## Метрики

| Метрика | Как считаем | Цель MVP |
|---|---|---|
| **Retrieval Recall@k** | Доля вопросов, где нужный источник попал в top-k (k=3/5) | >= 0.70 @5 |
| **Retrieval Precision@k** | Доля релевантных источников среди top-k | >= 0.50 @5 |
| **Answer Faithfulness** | Ответ опирается на найденные фрагменты (ручная оценка 0/1/2) | >= 80% оценок 1-2 |
| **Answer Correctness** | Фактическая корректность по эталону (ручная 0/1/2) | >= 70% оценок 1-2 |
| **Abstention Quality** | На вопросах "нет в корпусе" модель честно отказывается | >= 80% |
| **Latency p50/p95** | Время end-to-end ответа локально | p50 < 8s, p95 < 20s (RTX 3050) |

## Процедура прогона

1. Зафиксировать версию корпуса, индекса, модели, промпта.
2. Прогнать все вопросы через один и тот же скрипт.
3. Сохранить сырые ответы, retrieved chunks, latency.
4. Разметить вручную faithfulness/correctness по рубрике.
5. Посчитать агрегаты и сохранить в `reports/metrics-run-*.json`.

## Рубрика ручной оценки

- **2** — корректно, опирается на источник, без лишних выдумок.
- **1** — частично корректно или есть мелкая неточность/лишнее.
- **0** — неверно, галлюцинация, или игнорирует источник.

## Ограничения (признать явно)

- Датасет маленький и создан командой спринта — риск bias.
- Ручная оценка субъективна; для MVP допустимо, для продукта — нужны независимые разметчики.
- Метрики отражают демо-корпус, не обобщаются на произвольные домены.
- Latency зависит от прогрева, фоновой нагрузки, размера контекста.
