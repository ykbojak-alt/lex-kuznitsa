# LEX — одна страница для жюри

**Что это.** Ассистент, который отвечает сотруднику **только по регламентам
организации**. Не из интернета и не из памяти модели: каждое утверждение ответа
подтверждается цитатой; если в базе ответа нет — система не выдумывает, а задаёт
уточняющий вопрос или передаёт вопрос людям; ответ людей возвращается в базу как
кейс и с этого момента закрывает вопрос.

**Стенд:** `https://2.27.5.234.nip.io:4437` — внешний, все адреса `example.invalid`,
письма имитируются. Все числа ниже сняты с него **ночью 27.11.2026**: 103 прогона
плюс проверка полного цикла «заявка → кейс → ответ по кейсу».

## 2. Три критерия приёмки

### Критерий 1. Ответы строго по регламентам; нет ответа → запрос в службу качества

**Как устроено:** 9 шагов; поиск — BM25 + вектор + переранжирование; гейт
релевантности (покрытие предмета ≥ 0.75, близость ≥ 0.50); самопроверка — утверждение
без цитаты выбрасывается (порог сходства 0.45), если не подтверждено ничего —
отказ, а не ответ.

**Как выглядит на стенде:** «Какой порядок назначения ответственных на Заявку на
пресейл?» → **12.9–54.8 с**, покрытие предмета 100 %, уверенность 0.8x, оговорка
`low/medium`, цитата `КД-ПД-03` / `КД-ПС-02` — **7 ответов из 9 прогонов**.
Запасной с самой узнаваемой цитатой: «Как проводится анкетирование заказчика о
качестве выполненного проекта?» → 12.6–72.6 с, **6/9**, цитата `КД-ПД-03` п. 21.1
(«За анкетирование … отвечает Менеджер по качеству»). Шаг «Самопроверка» на экране:
«утверждений N · покрыто цитатами N · **внешних знаний 0** · оборвано N».

**Когда нормы нет:** заявка в очередь службы качества. «Как оформляются пропуска
подрядчиков в офис на проектах по пресейлу?» → **10 из 10 прогонов — заявка**,
4–9 с, **токены 0**: тема не покрыта корпусом (покрытие предмета 50 % при пороге
0.75), решение принимает гейт, а не модель. После ночной сверки в очереди СК 27 тикетов
(24 открытых) — перед записью очередь сбрасывают.

### Критерий 2. Уточняющий диалог при неоднозначности

2–3 итерации, конкретный вопрос — «О каком заказе, договоре или поставщике идёт
речь? (номер или предмет)»; поток закрывается без «готово». **Направление система больше
не спрашивает** — уточнение идёт про предмет. Цена уточнения не одинакова: **до
поиска** — 3–8 мс без модели (20 из 42 случаев на стенде), **после каскада** —
6–36 с и 1–4 вызова модели (22 из 42, максимум 133 с). Частота: 11 уточнений из
103 ночных прогонов (11 %), в журнале стенда — 42 из 322 (13 %) — корпус
покрывает узкую тему, см. `docs/LEX-LIMITS.md` §2.

### Критерий 3. Дообучение: вопрос → ответ службы качества → база

Заявка уходит в очередь СК → ответ вносит **человек** → кейс появляется в базе →
тот же вопрос отвечается уже по кейсу, с честной пометкой «по практике, регламент
не покрывает» (это не норма). **Полный цикл проверен на стенде 27.11.2026:** тикет
`LEX-2026-0022` → `POST /api/tickets/{tid}/answer` → кейс `case-0003`
(`source: quality_ticket`, `normative: false`, `public: false`) → повторный вопрос
«Как оформляется допуск на объект по проекту?» отвечен **по кейсу за 46.4 с**:
цитата `source_kind: case` на `case-0003`, текст цитаты «Вопрос: … В практике: …»,
оговорка `medium`, токены 6 826, 2 вызова.

## 4. Честные ограничения

Полный разбор — `docs/LEX-LIMITS.md`. Коротко:

* **Корпус только из выданных документов** — нет документа, нет ответа. Это
  критерий приёмки, а не дефект.
* **~13 % вопросов журнала уходят в уточнение** (42 из 322): четыре регламента
  покрывают узкую тему; в ночных прогонах — 11 из 103.
* **1–4 LLM-вызова на вопрос**, без многошагового агентного поиска.
* **OCR недоступен** — сканы не читаются; корпус markdown.
* **Редакций нечего разрешать**: `conflict_rules` в `corpus-real` = 0.
* Ответ может прийти с оговоркой «сверьтесь с цитатой» — это признак проверки;
  из кадра оговорку не вырезаем.
* Вне компетенции система даёт **отказ с объяснением**, а не заявку (решение
  владельца): заявка — для вопроса внутри компетенции, но без нормы.
* «Дообучение» = кейс из практики; регламент не переписывается автоматически.
* Экран аналитики (`GET /api/stats`) **на стенде работает (200)**; цифры выше сняты
  и из него, и из `/api/analytics`. Счётчики считают **накопленный** журнал.

## 5. Проверка за минуту

```bash
curl -s https://2.27.5.234.nip.io:4437/api/health
curl -s https://2.27.5.234.nip.io:4437/api/roles
curl -sN -X POST https://2.27.5.234.nip.io:4437/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"Как проводится анкетирование заказчика о качестве выполненного проекта?","role_id":"director"}'
```

Второй ответ — 5 ролей с `read_mode: department_read` и числом доступных
документов у каждой (`technical` 1 из 4, `ib` 2 из 4, `director` 4 из 4);
третий — SSE-поток целиком: 9 шагов, ответ с цитатой из регламента и оговоркой
`low/medium`.

**Почему 9 шагов, а не 11:** шаги `resolve` и `conflict` относятся к редакциям,
а в `corpus-real` правил редакций нет — каскад их пропускает, а не выводит
пустые строки (`src/lex/orchestrator.py:392-403`). На `sample-corpus`, где
правила есть, шагов 11.
