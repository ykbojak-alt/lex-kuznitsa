## 3. Сценарий: три кадра, в этом порядке

Порядок важен: отказ `out_of_scope` — самый быстрый (0.3–5.3 с, 0 токенов), его
снимаем **первым**, чтобы он не зависел от состояния слота.

### Кадр 1 (0:20–0:35) — ответ с цитатой

| | |
|---|---|
| Вопрос | **«Какой порядок назначения ответственных на Заявку на пресейл?»** |
| Ожидаемо | `answer`, **7/9** (2/2 на текущем слоте), 12.9–54.8 с |
| В кадре | шаги `[1/9]…[9/9]`, «предмет 100 %», ответ, блок «Источники» с `КД-ПД-03` / `КД-ПС-02` |
| Доказательство | цитата с `doc_id` + редакция + дата; `verify` показывает подтверждённые утверждения |

Это самый длинный кадр. Если ответ дольше ~40 с — ускорять **только** ожидание
(титр «×N, ожидание модели»), не результат.

### Кадр 2 (0:35–0:50) — отказ вне компетенции

| | |
|---|---|
| Вопрос | **«Какая ставка НДС в России?»** |
| Ожидаемо | `refusal out_of_scope`, 3/3, 0.4–3.5 с, **0 токенов** |
| В кадре | `[1/9]` → `[2/9]`, «ВНЕ КОМПЕТЕНЦИИ: направление не определено», база покрывает: перечень направлений |
| Доказательство | прогон **оборвался на шаге 2**, модель не вызывалась — в кадре видно, что это гейт, а не «модель не смогла» |

**Риск на 12 документах — низкий, и вот почему.** `out_of_scope` решается по
`_line_of_text` + `_coverage` (`policy.py:299`, порог `POLICY_MIN_SCORE=0.15`,
`POLICY_MIN_COVERAGE=0.08`). «НДС» в `corpus-norm/` **не встречается вовсе**
(`grep -ril "НДС" corpus-norm/` → 0 файлов).

Отдельно проверила `_coverage` (`policy.py:243-266`): она строит путь как
`corpus.root / doc.file`, а после слияния `corpus.root` = **`corpus-real`**
(`load_corpus_multi` берёт `bases[0]`, `corpus.py:266`). У внешних документов
`file` = `КН-А1-ГК-РФ.md`, такого файла в `corpus-real/` нет → `head = ""`, и в
термины попадает **только заголовок** («КН-А1-ГК-РФ — выборка статей …»), без
тела документа. То есть слова «аренда»/«ставка» из тела внешних актов на
`_coverage` **не влияют** — вердикт `out_of_scope` по НДС и по аренде должен
устоять.

> Это побочный дефект сам по себе (покрытие для внешних документов считается по
> заголовку, а не по тексту), но он не мой: `src/lex/policy.py`. В сценарии он
> **работает в нашу пользу** — эталонные отказы не размываются.

Всё равно **перепрогнать перед съёмкой** — я прогоны не запускаю, а замеры в
`DEMO-CHECKLIST.md` сделаны на 4 документах.

Запасной вопрос, если НДС всё же уйдёт в поиск: **«Сколько стоит аренда офиса
в месяц?»** — на 4 документах 3/3 `refusal`, 1.1–3.8 с.

### Кадр 3 (0:50–1:30) — честный отказ модели (`model_refusal`)

| | |
|---|---|
| Вопрос | **«Какие требования к лицензированию установлены в Гражданском кодексе РФ?»** |
| Ожидаемо | `refusal model_refusal` — фрагменты **нашлись**, модель отказалась отвечать |
| В кадре | `retrieve`: `BM25 20 · вектор 0 → 20 → 20`, «предмет 100 % · близость 0.00», `doc_ids` = КН-А2 ×5, КН-А3 ×1 + 3 кейса; `permissions`: «полный корпус (12 документов)»; `compose`: «модель вернула отказ» |
| Доказательство | это **не** «нет в корпусе»: `_why_unresolved` для `model_refusal` пишет «модель отказалась отвечать по найденным фрагментам: <причина>» (`dialogue.py:1126-1131`) |

**Этот кадр существует только на 12 документах.** `model_refusal` возникает, когда
модель сама ответила `ОТКАЗ: <причина>` по инструкции промпта
(`orchestrator.py:1545-1546`, детектор `1050-1052`). На 4 регламентах по вопросу про
лицензирование фрагментов не будет вовсе → сработает `not_in_corpus`
(`orchestrator.py:1023-1032`), и кадр будет другим.

**Отсюда прямое противоречие, которое надо решить ALICE:**
- снимаем на **4** документах → нет `model_refusal`, кадр 3 заменяется на
  `not_in_corpus` (тоже честный отказ, но другой текст и другой смысл);
- снимаем на **12** документах → есть `model_refusal`, но надо перепрогнать
  кадры 1–2 и проверить, что `out_of_scope` устоял.

Третий вариант — снять **оба** отказа на 12 документах (НДС + лицензирование) и
взять ответ по регламенту как есть: тогда кадры 2 и 3 оба живут на 12.
