# DEMO-FIXTURES — пять фикстур для демо-видео LEX

> **Назначение:** определить, что агент LEX должен ответить в демо-видео, чтобы каждый
> тип случая был задемонстрирован предсказуемо: есть ответ со ссылкой на источник,
> есть обоснованный отказ. Корпус фикстур — локальный: ответы проверяются по
> `sample-corpus/` и `docs/ARCHITECTURE.md` перед съёмкой.
>
> **Статус:** pre-sprint материал. Фикстуры соответствуют типам из `docs/DEMO-SCRIPT.md`
> (сцена 1–3: факт/расчёт, сцена 4: конфликт редакций, сцена 5: отказ, сцена 7: аналитика).

---

## Фикстура 1 — тип: факт

- **Вопрос:** «Сколько документов в корпусе на момент генерации отчёта?»
- **Ожидаемый ответ:** число документов, указанное в источнике, из которого LEX делает
  выборку (отсылка: `<файл>` в корпусе).
- **Ожидаемые цитаты:** пункт, где указано количество (или состав корпуса).
- **Примечание:** ответ должен быть без выдумок; если цифра не подтверждена документом —
  агент должен сказать «не нашёл подтверждение», а не отгадывать.

## Фикстура 2 — тип: расчёт

- **Вопрос:** «Какова выручка при кросс-продаже при параметрах [X, Y]?»
- **Ожидаемый ответ:** число, пересчитанное по формуле из корпуса (отсылка:
  `sample-corpus/` или `docs/ARCHITECTURE.md`), плюс порядок расчёта.
- **Ожидаемые цитаты:** формула/таблица с входными данными.
- **Примечание:** ответ без округлений в угоду, если параметры не совпали — тогда должна быть
  видна причина (какая входная цифра не найдена).

## Фикстура 3 — тип: конфликт редакций (сцена 4)

- **Вопрос:** «Назовите позицию документа про [тему]» (варианты противоречат друг другу).
- **Ожидаемый ответ:** две позиции — отражённые буквально, со ссылками на документы,
  где они сказаны; итог: «две редакции друг от друга не разделены данными».
- **Ожидаемые цитаты:** конкретные фразы из двух документов, из которых вытекают позиции.
- **Ожидаемая причина отказа:** нет — отказа быть не должно, нужен верный ответ.

## Фикстура 4 — тип: обоснованный отказ (сцена 5)

- **Вопрос:** запрос, на который агент не может дать утверждённый ответ, потому что
  он противоречит документам (пример из `docs/ARCHITECTURE.md` §6 «Отказ»).
- **Ожидаемый ответ:** формулировка отказа («не могу ответить без подтверждения») +
  обоснование: какие пункты противоречат запросу.
- **Ожидаемые цитаты:** фрагменты документов с противоречащими утверждениями.
- **Ожидаемая причина отказа:** ссылка на состояние документа (например, «документ
  не определяет этот сценарий»).

## Фикстура 5 — тип: аналитика журнала (сцена 7)

- **Вопрос:** «Какие выводы из журнале [тема] можно сделать на основе записей за период?»
- **Ожидаемый ответ:** 3–5 конкретных выводов с цифрами, источник — записи журнала.
- **Ожидаемые цитаты:** извлечённые отрывки из записей (таймстампы + текст), которые
  поддерживают каждый вывод.
- **Примечание:** без придуманных паттернов — только заметки, подтверждённые записями.
