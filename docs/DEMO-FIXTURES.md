# DEMO-FIXTURES — что должно быть на экране в демо-видео LEX

> **Назначение:** фикстура — это не «вопрос», а **проверяемое ожидание**: какой шаг
> появится, какая цитата на экране, какой номер выдаст система. Если в кадре шаг
> или цитата не совпали — дубль переписывается.
>
> **Корпус фикстур:** `corpus-real/` — 4 регламента заказчика (154 чанка).
> Все цитаты ниже — **дословно из этих документов**; ничего не выдумано.
> Проверено прогоном через API 26.11.2026, роль `director` («Руководитель»).
>
> **Роль в демо — `director`.** С 26.11.2026 роли = реальные отделы (v1.16):
> `GET /api/roles` отдаёт `technical`, `ib`, `dbrct`, `quality`, `director`.
> Старой роли `lawyer` («Юридический отдел») больше нет: `POST /api/ask` с
> `role_id=lawyer` → `400 {"detail":"неизвестная роль: lawyer"}`
> (`src/api/app.py:199`, список ролей — `src/api/core.py:236`).
> `director` видит все 4 документа, поэтому все цитаты ниже сохраняются.
>
> **Порядок актов = критерии жюри:** акты А/Б/В → `docs/VIDEO-STORYBOARD.md`.

## A-1 — акт А: ответ строго по регламенту, с цитатами

**Вопрос в кадре:**

> «Как проводится анкетирование заказчика о качестве выполненного проекта?»

**Что должно произойти по шагам (реальные строки из прогона):**

| Шаг | Кадр |
|---|---|
| 1 `accept` | «роль Руководитель, дата отсчёта 2026-11-26» |
| 2 `policy` | «в компетенции: да · направление: проектная деятельность» |
| 3 `decompose` | «1 подвопрос» |
| 4 `inspect` | «текст 4 · картинки 0 · сканы 0 · смешанные 0» |
| 5 `retrieve` | «BM25 16 · вектор 16 → кандидатов 24 · после rerank 24 · предмет 100% · близость 0.74» |
| 6 `cases` | «найдено 0 кейсов» |
| 7 `permissions` | «чтение: полный корпус (4 документов) · запись: разрешена» |
| 8 `resolve` | «правило не определено — действует как есть» |
| 9 `conflict` | «конфликтов: 0; фрагментов 24» |
| 10 `compose` | «из 6 фрагментов» |
| 11 `verify` | «утверждений 20 · покрыто 16 · 4 отброшено (нет цитаты) · оборвано 2 · уверенность 0.67 · ОГОВОРКА (medium)» |

**Ожидаемые цитаты (дословно из корпуса):**

* `КД-ПД-03`, раздел «21. Анкетирование заказчика о качестве выполненного проекта»:
  «21.1. За анкетирование заказчика о качестве выполненного проекта отвечает
  Менеджер по качеству. Для сервисных проектов анкетирование проводится ежеквартально.»
* `КД-ПД-01`, раздел «22. Анкетирование заказчика о качестве выполненного проекта»:
  «22.1. За анкетирование заказчика о качестве выполненного проекта отвечает
  Менеджер по качеству.»

**Что доказывает этот критерий:** ответ собран **только** из регламентов базы: в
повторном прогоне (78 с) агент сослался на **два независимых** регламента
(`КД-ПД-03` + `КД-ПД-01`), в первом (81 с) — на один (`КД-ПД-03`). Состав цитат
зависит от того, что попало в выдачу: **требование фикстуры — цитата есть и
указывает на пункт регламента**, а не ровно две. Ни одного утверждения «из опыта» —
всё подтверждено цитатой, неподтверждённое выброшено (шаг `verify`: «4 отброшено
(нет цитаты)»).

**Не должно быть:** выдуманных сроков, сведений о документах, которых нет в
корпусе, и ответа без единой цитаты. Оговорку (`medium`) с экрана **не убирать**.

## B-1 — акт Б: вопрос вне базы → заявка в службу качества

**Вопрос в кадре:**

> «Какой срок хранения первичных бухгалтерских документов?»

**Что должно произойти по шагам:**

| Шаг | Кадр |
|---|---|
| 2 `policy` | «в компетенции: да · направление: хранение» — вопрос **внутри** компетенции |
| 5 `retrieve` | «предмет 33% · близость 0.48 · **предмет вопроса не найден (33%)**» |
| `escalate` | «заявка `esc-0001`: в корпусе нет документа по теме «срок хранения первичных
  бухгалтерских документов» (ближайшее по теме: `КД-ПС-02`, `КД-ПД-04`, `КД-ПД-04`,
  ответа по теме в них нет)» |

**Письмо (имитация, §22.2):** получатель `quality@example.invalid`, отправитель
`director@example.invalid` (адрес — из роли, `src/api/config.py:64`), тема «[LEX]
Вопрос без ответа в базе: Какой срок хранения первичных бухгалтерских документов?»,
`delivery: simulated`, срок «до 2 рабочих дней», подпись «Заявка передана в службу
качества. Ответ появится в базе как кейс.»

**Номера (на чистом стенде — первые):** заявка `esc-0001`; тикет в очереди СК
`LEX-2026-0001` (в прогоне 26.11 очередь была пустой, поэтому номер первый; при
непустой очереди номер больше). В очереди СК заявка лежит **связанной** с заявкой
полем `escalation_id`, а в самом тикете — `asker.role_id: "director"`.

**Что доказывает этот критерий:** агент **не подставил** правдоподобное «5 лет» из
своих знаний — он сказал, что такой нормы в регламентах нет, и передал вопрос
людям. Оговорки «по практике» в этом кадре быть не должно.

## Не годится в запасной кадр: «Кто согласует ТКП в пресейле?»

Поведение нестабильно, в прогонах 26.11: `error` на стадии `compose` (таймаут LLM,
пустое сообщение об ошибке) → в двух повторах `answer` (59 с: 3 цитаты `КД-ПД-01`,
`КД-ПД-01`, `КД-ПС-02`; 67 с: 2 цитаты `КД-ПД-01`); в прогоне до v1.16 тот же вопрос
давал `clarify`.
Если вопрос задан и пришёл `answer` — кадр годится на замену акта А, но **не** как
уточнение. В ролях `technical`/`dbrct` ответ будет иным (свой отдел).

## C-1 — акт В: ответ СК → кейс → повторный вопрос отвечен из кейса

Три шага, все проверены:

**Шаг 1 — служба качества отвечает.** В очереди СК открыт тикет из B-1; ответ
вводится вручную (в демо — так и должно быть: человек, а не агент):

> «Первичные бухгалтерские документы хранятся пять лет со дня составления.»

`POST /api/tickets/{tid}/answer` → тикет получает `status: answered`.

**Шаг 2 — кейс появился в базе.** `GET /api/cases`:

| Поле | Значение |
|---|---|
| `id` | `case-0001` |
| `question` | «Какой срок хранения первичных бухгалтерских документов?» |
| `answer_in_practice` | «Первичные бухгалтерские документы хранятся пять лет со дня составления.» |
| `author_role` / `author_name` | `quality` / «служба качества» |
| `outcome` | `resolved` |
| `source` / `escalation_id` | `quality_ticket` / `esc-0001` |
| `ticket_id` / `case_origin` | `LEX-2026-0001` / `auto` — кейс создан автоматически из ответа СК |
| `linked_docs` / `rule_key` | пусто — регламент этого не покрывает |
| `normative` | `false` — кейс не нормативен |
| `public` | `false` — практика отдела, не общая |

**Шаг 3 — тот же вопрос, новая сессия.** `POST /api/ask` с тем же текстом:

| Шаг | Кадр |
|---|---|
| 5 `retrieve` | «предмет 33% · близость 0.48 · предмет вопроса не найден (33%) · **тема закрыта кейсом из практики**» |
| 6 `cases` | «**найдено 1 кейс**» |
| 9 `conflict` | «конфликтов: 0; фрагментов 0» — из документов ничего, только кейс |
| 10 `compose` | «из 1 фрагментов» |
| 11 `verify` | «утверждений 2 · покрыто 1 · 1 отброшено (нет цитаты) · уверенность 0.87 · ОГОВОРКА (medium)» |

**Ответ:**

> «По практике, регламент не покрывает: первичные бухгалтерские документы хранятся

Цитата — на `case-0001` (`source_kind: case`), а не на документ.

**Что доказывает этот критерий:** система не «выучила корпус» — она **запомнила
ответ человека** и теперь отвечает по нему, честно называя это практикой, а не
нормой.

## X-1 — отказ вне компетенции (запасной кадр)

**Вопрос:** «Какая ставка НДС в России?»

**Ожидаемый кадр:** `refusal`, `kind: out_of_scope`, причина «Вопрос не
относится к базе знаний организации», подсказка «База покрывает: проектная

**Тон ответа:** «не могу ответить» + **что именно** не покрыто. Не извиняться и не
подставлять «20 %».

## Что проверять в каждом дубле

1. Номер заявки и номер тикета — **новые** (в кадре не должно быть вчерашних).
2. Цитаты — из `corpus-real`, дословно; при двух цитатах — два разных `doc_id`.
3. Оговорка (`medium`) на месте, текст ответа не вырезан.
4. В кадре нет адресов, кроме `example.invalid`, и нет ключей.
5. Время акта А уложилось в тайминг из `docs/DEMO-CHECKLIST.md` §4.
6. Роль в кадре — «Руководитель» (`director`), не «Юридический отдел»: старая роль
   на стенде отвергается с 400.
