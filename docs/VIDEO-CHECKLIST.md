# VIDEO-CHECKLIST.md — приёмочный чек-лист видео перед сдачей жюри

**Статус:** pre-sprint материал (2026-11-25). Код продукта не пишется до старта спринта.

**Что это.** Гейт, через который проходит **каждый** финальный видеофайл (демо-видео и
питч-видео) перед отправкой. Задача — поймать то, что ломает сдачу, а не пересказать
сценарии.

**Чем не дублирует соседей:**
- `docs/DEMO-SCRIPT.md` §4 — «стоп-условия» *во время съёмки* (когда прервать дубль).
- Этот файл — приёмка *готового файла*: техника, звук, тайминг, содержание, соответствие
  Положению. Дополняет, а не заменяет.

**Правило прохода:** чек-лист считается пройденным, только если отмечены **все**
обязательные пункты (🔴). Пункты 🟡 — желательные, их пропуск фиксируется в отчёте, но
не блокирует сдачу. Один непройденный 🔴 = файл на сдачу не идёт.

---

## 0. Какие файлы проверяем

| Файл | Что это | Лимит |
|---|---|---|
| `lex-demo-<sha8>-<date>.mp4` | демо-видео (прогон LEX) | ≤ 3:00 |
| `lex-pitch-<sha8>-<date>.mp4` | видео-питч | ≤ 1:30 |

Оба проходят секции 1–5. Секция 6 (критерии) — отдельно для демо и для питча.

---

## 1. Техническое качество

| # | Проверка | Как проверить | Ур. |
|---|---|---|---|
| 1.1 | Разрешение 1920×1080 (16:9) | `ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv=p=0 file.mp4` | 🔴 |
| 1.2 | Частота кадров 30 fps | `ffprobe ... -show_entries stream=r_frame_rate` → `30/1` | 🔴 |
| 1.3 | Кодек H.264 High, `yuv420p` | `ffprobe ... -show_entries stream=codec_name,pix_fmt` | 🔴 |
| 1.4 | Контейнер MP4 с `+faststart` | `ffprobe -v trace` показывает `moov` до `mdat`; либо `mp4box -info` | 🔴 |
| 1.5 | Размер ≤ лимита (100 МБ демо / 60 МБ питч) | `ls -l file.mp4` | 🔴 |
| 1.6 | Нет артефактов сжатия на тексте терминала | просмотр на 100% и на 720p | 🔴 |
| 1.7 | Файл открывается в обычном плеере (VLC/браузер) без ошибок | открыть в двух плеерах | 🔴 |
| 1.8 | Нет чёрных кадров/зависаний в начале и в конце | проскроллить первые/последние 3 с | 🟡 |

## 2. Звук

| # | Проверка | Как проверить | Ур. |
|---|---|---|---|
| 2.1 | Голос разборчив, без эха/гула | прослушать в наушниках и в колонках | 🔴 |
| 2.2 | Громкость голоса −16 LUFS (±1) | `ffmpeg -i file.mp4 -af loudnorm=print_format=summary -f null -` | 🔴 |
| 2.3 | True-peak ≤ −1 dBTP (нет клиппинга) | тот же `loudnorm` summary, смотреть `Output True Peak` | 🔴 |
| 2.4 | Нет скачка громкости на стыке вводка/тело/аутро | прослушать стыки | 🔴 |
| 2.5 | Фоновая музыка (если есть) не перекрывает голос | прослушать речевые участки | 🟡 |
| 2.6 | Нет посторонних звуков (уведомления, клавиши, чужие голоса) | прослушать целиком | 🔴 |
| 2.7 | Тишина в начале/конце — не обрезана резко | прослушать первые/последние 2 с | 🟡 |

## 3. Тайминг

| # | Проверка | Как проверить | Ур. |
|---|---|---|---|
| 3.1 | Демо ≤ 3:00 (цель 2:50) | `ffprobe -show_entries format=duration` | 🔴 |
| 3.2 | Питч ≤ 1:30 (цель ≤ 1:28) | `ffprobe -show_entries format=duration` | 🔴 |
| 3.3 | Запас ≥ 10 с до лимита у демо | (3:00 − длительность) ≥ 10 | 🔴 |
| 3.4 | Тайминги шагов `[N/7]` совпадают с `scenes-*.ts` и с тем, что видно в UI | сверка по кадрам | 🔴 |
| 3.5 | Два полных прогона демо уложились в лимит (не случайность) | замер обоих | 🟡 |
| 3.6 | Ни одна сцена не «висит» дольше, чем нужно для смысла | просмотр по сценам | 🟡 |

## 6. Соответствие критериям жюри

### 6a. Демо-видео — 6 критериев (0–3 балла каждый)

| # | Критерий | Есть сцена-доказательство | Ур. |
|---|---|---|---|
| 6a.1 | Соответствие задаче партнёра | сцена 5 (отказ) + 6 (аналитика) | 🔴 |
| 6a.2 | Корректность реализации | сцены 3–4 (редакция + цитата + verify) | 🔴 |
| 6a.3 | Агентность | сцены 2–4 (счётчик `[N/7]`, реальные числа) | 🔴 |
| 6a.4 | Степень готовности | сцены 0–1 (честная вводка, версия) + 7 (закрытие) | 🔴 |
| 6a.5 | Потенциал внедрения | в видео **не закрывается** — это нормально, есть в питче | — |
| 6a.6 | Экономика эксплуатации | в видео **не закрывается** — в питче и ONE-PAGE | — |

> 6a.5 и 6a.6 — не провал чек-листа: видео доказывает *работу*, применимость доказывают
> питч и описание. Проверяем, что остальные четыре присутствуют.

### 6b. Питч-видео — те же 6 критериев

| # | Критерий | Блок питча | Ур. |
|---|---|---|---|
| 6b.1 | Соответствие задаче партнёра | 1 + 2b/2d | 🔴 |
| 6b.2 | Корректность реализации | 2a–2c | 🔴 |
| 6b.3 | Потенциал внедрения | 4 (три шага пилота) | 🔴 |
| 6b.4 | Готовность | 2 + 3 (честные границы) | 🔴 |
| 6b.5 | Агентность | 2a (`[N/7]`) | 🔴 |
| 6b.6 | Экономика эксплуатации | 4 (стоимость по факту) | 🔴 |

## 9. Быстрые команды проверки (для отчёта)

```bash
# длительность + разрешение + fps + кодек одной строкой
"$FFPROBE" -v error -select_streams v:0 \
  -show_entries stream=width,height,r_frame_rate,codec_name,pix_fmt \
  -show_entries format=duration -of default=nw=1 "file.mp4"

# громкость и true-peak
"$FFMPEG" -i "file.mp4" -af loudnorm=print_format=summary -f null - 2>&1 | \
  grep -E "Input Integrated|Output Integrated|Output True Peak"

# размер и хэш
ls -l "file.mp4"; sha256sum "file.mp4"
```

(`$FFMPEG` / `$FFPROBE` — из `D:\tools\ffmpeg\`.)
