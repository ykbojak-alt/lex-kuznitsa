# DEPLOY-NEXUSLINK — подключение к Nexus Link (основной путь инференса)

**Статус:** подключение **проверено фактически** (2026-11-26, до старта спринта).
`GET /v1/models` → 200, `POST /v1/chat/completions` → 200 с непустым ответом,
`POST /v1/messages` → 200. Слот `NEXUS_LINK_MODEL=claude-sonnet-5`. Значения
токенов и внутренние адреса в этом документе **не приводятся** — только имена
переменных.

**Основа:** архитектурное решение ALICE — основной путь инференса Nexus Link,
локальная модель Qwen3-8B как fallback. Методика оценки — `docs/EVAL-HARNESS.md`,
модельный слой — `docs/MODEL.md`.

---

## 0. Правило безопасности, из которого следует всё остальное

Репозиторий спринта — внешний артефакт. Поэтому в нём **нет**:

- адресов внутреннего контура (IP, доменов, портов с внутренними адресами);
- значений токенов, ключей и паролей — ни в коде, ни в документации, ни в отчётах.

Адрес приходит через переменную окружения, токен — через переменную окружения или
секрет-хранилище CI. В репозитории хранятся только **имена** переменных.

---

## 1. Переменные окружения

| Переменная | Что это | Обязателен |
|---|---|---|
| `NEXUS_LINK_BASE_URL` | базовый URL основного пути инференса | да, если основной путь используется |
| `NEXUSLINK_KEY` | токен доступа к Nexus Link | да, если основной путь используется |
| `NEXUS_LINK_MODEL` | слот модели на основном пути | желательно задать явно |
| `LOCAL_MODEL_BASE_URL` | базовый URL локального fallback-сервера | нет (по умолчанию `http://127.0.0.1:8080/v1`) |
| `LOCAL_MODEL_NAME` | имя локальной модели | нет (по умолчанию `Qwen3-8B-Instruct-Q4_K_M`) |

Имя переменной с токеном можно переопределить флагом `--nexus-link-key-env` —
передаётся **имя**, а не значение.

Адрес основного пути и имя переменной с токеном можно задать флагами
`--nexus-link-url` и `--nexus-link-key-env` соответственно. Приоритет:
**флаг → переменная окружения → ничего не задано** (тогда основной путь считается
недоступным, скрипт это печатает и предлагает fallback).

---

## 2. Где взять адрес и токен

- **Адрес** (`NEXUS_LINK_BASE_URL`) выдаёт владелец Nexus Link — M.E.R.C. (sage-pl).
  Значение прописывается в окружении машины разработки и в секретах CI. В репозитории
  его нет; в отчётах и логах оно не печатается.
- **Токен** (`NEXUSLINK_KEY`) — мастер-токен контура Nexus Link. Он хранится в
  конфиге шлюза на машине, где шлюз запущен (`~/.nexuslink/config.json`, поле
  `incoming_token`). **Значение не читается агентами и не копируется в репозиторий.**
  Передача — только через окружение или секрет-хранилище.
- Если ключа для внешнего сервиса в вашей подборке нет — запросите его у владельца
  Link. Самостоятельно сгенерировать или подобрать ключ нельзя.

Карта портов, поверхностей и проверяющих сторон живёт во внутренней документации
фермы и в репозиторий спринта **не переносится** — это часть причины, по которой
здесь нет ни одного адреса.

## 3. Эндпоинты

**Проверено 2026-11-26:** все три отвечают 200 на нашем входе, токен в
`Authorization: Bearer` принимается.

| Эндпоинт | Назначение | Результат проверки |
|---|---|---|
| `GET /v1/models` | список слотов | 200, 7 слотов |
| `POST /v1/chat/completions` | OpenAI-совместимый вызов | 200, `provider: Baidu`, `cost: 0` |
| `POST /v1/messages` | Anthropic-совместимый вызов | 200, 1.5 с |

Важно про `/v1/chat/completions`: имя слота в `model` — это **id слота**
(`claude-sonnet-5`), а не имя апстрим-провайдера. Ответ несёт `"model"` с
реальным апстримом (`baidu/ernie-5.5-flash-preview:free`) и `"provider"`.
Слот — это маршрут «через OpenRouter free», поэтому состав апстримов
меняется, а стоимость нулевая. Считать стабильной можно только схему
ответа, не конкретную модель.

Отдельная ловушка: `POST /v1/messages` с `max_tokens` меньше нужного
возвращает только блок `thinking` и `stop_reason: "max_tokens"` — без
`text`. Для оценки качества RAG давайте запас (≥ 1024) и проверяйте, что в
`content` есть блок `type: "text"`, а не только `thinking`.

## 4. Проверка доступности

Заголовок с токеном формируется из переменной окружения; **значение токена не
печатается и не попадает в список процессов** (в обвязке заголовок уходит в curl
через stdin).

```bash
# адрес и токен — из окружения; ничего не хардкодится
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: Bearer $NEXUSLINK_KEY" \
  "$NEXUS_LINK_BASE_URL/v1/models"
```

Как читать код ответа:

| Код | Значение | Действие |
|---|---|---|
| `200` | адрес живой, токен принят | основной путь доступен, работаем через него |
| `401` / `403` | адрес живой, токен отклонён или не задан | **переходим на локальный fallback**; проверить `NEXUSLINK_KEY` |
| `000` | таймаут или соединение не установлено | **переходим на локальный fallback**; проверить адрес и сеть |
| прочие `4xx`/`5xx` | адрес живой, но запрос не обслуживается | разбираться у владельца Link; fallback |

Быстрая проверка без токена (нужна, чтобы отличить «сеть не работает» от
«неверный ключ»):

```bash
curl -s -o /dev/null -w '%{http_code}\n' "$NEXUS_LINK_BASE_URL/v1/models"
```

Ожидаемый ответ — `401`: это означает «адрес достижим, авторизация требуется».

## 5. Fallback: локальная модель

Правило переключения:

1. основной путь (Nexus Link) отвечает `200` с принятым токеном → **работаем через
   него**, локальная модель не трогается;
2. основной путь отвечает `401`/`403` или не отвечает (таймаут) → **уходим на
   локальную модель**;
3. локальная модель тоже недоступна → путь инференса не определён, прогон
   инференса невозможен (демо-обвязка без модели при этом продолжает работать).

Локальный fallback — Qwen3-8B-Instruct (GGUF Q4_K_M) на llama.cpp server,
подробности запуска и требования к железу — в `docs/MODEL.md`. Проверка
доступности локального сервера:

```bash
curl -s -o /dev/null -w '%{http_code}\n' "${LOCAL_MODEL_BASE_URL:-http://127.0.0.1:8080/v1}/models"
```

## 6. Проверка через обвязку

`demo/run-local.sh` выполняет ту же проверку на шаге 2/4 и печатает активный путь:

```bash
# адрес и токен из окружения
sh demo/run-local.sh

# адрес и имя переменной с токеном — флагами
sh demo/run-local.sh --nexus-link-url "$NEXUS_LINK_BASE_URL" \
                     --nexus-link-key-env NEXUSLINK_KEY

# основной путь должен быть пригоден, иначе код возврата 1
sh demo/run-local.sh --require-inference
```

Что печатается:

- состояние основного пути (HTTP-код, адрес) и состояние локального fallback;
- состояние токена: `задан (env NEXUSLINK_KEY, значение не выводится)` — само
  значение не выводится никогда;
- **активный путь**: `nexus-link` / `local-fallback` / `не определён`.

Активный путь пишется в артефакт прогона `stub-summary.json` (поле
`inference_path`) — по нему видно, на чём шёл конкретный прогон. Прогоны на
разных путях несопоставимы (см. `docs/EVAL-HARNESS.md` §7).

`NEXUS_LINK_MODEL`. Перед прогоном: `set -a; . ./.env; set +a`.
