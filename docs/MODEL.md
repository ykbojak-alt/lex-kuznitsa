# ИИкузница — модельный слой (Q9)

**Лицензия нашего кода: MIT** (см. `LICENSE`). Внешние компоненты ниже несут свои
лицензии — они не наши и не перелицензируются.

**Решение владельца 26.11:** локальная LLM **не поднимается**. Вопрос закрыт.
Инференс — sage-pl через NexusLink. Ниже описано то, что есть на самом деле.

## Что реально работает (проверено 26.11)

| Компонент | Что это | Где | Статус |
|---|---|---|---|
| **LLM** | NexusLink, слот `claude-sonnet-5` | sage-pl, `/v1` за Caddy | работает, 200, `cost: 0` |
| **Embedding** | `bge-m3`, dim 1024 | `127.0.0.1:8081`, CPU | работает |
| **Reranker** | `bge-reranker-base` | `127.0.0.1:8082`, CPU | работает |
| **Корпус** | 27 документов, 92 вопроса | `sample-corpus/` | работает |

### Важное различие: обработка локальна, LLM — нет

- **Эмбеддинги и реранк — полностью локальны.** Ни один фрагмент документа
  не покидает машину при индексации и ранжировании. Это реальный аргумент
  к критерию «Экономика эксплуатации» — стоимость этих шагов ноль, и они
  не зависят от внешнего сервиса.
- **LLM — через NexusLink.** Слот `claude-sonnet-5` маршрутизируется в
  OpenRouter (апстримы меняются: Baidu, Nvidia). То есть генерация — внешний
  вызов, через собственный шлюз на нашем сервере sage-pl.

**Не называть это «локальной моделью».** Организаторы (офиц. ответ №8) пишут
«локально развёрнутую модель, а не обращение к внешнему LLM API» — наш путь
этому не соответствует буквально, и в описании продукта эвфемизм недопустим.
См. `docs/ORGANIZER-ANSWERS-20261126.md` §3.

### Что говорить жюри (честная формулировка)

> «Модель — через шлюз NexusLink на нашем сервере. Эмбеддинги и реранкер
> развёрнуты локально: индексация и ранжирование корпуса не выходят наружу.
> Документы обезличены заказчиком. Стоимость запроса — ноль: апстрим идёт
> по free-тарифу, шлюз наш.»

## Адреса и переменные

- `NEXUS_LINK_BASE_URL` — базовый URL шлюза (в репозиторий не попадает).
- `NEXUSLINK_KEY` — токен Bearer. Только через `.env` (в `.gitignore`).
- `NEXUS_LINK_MODEL` — **`claude-sonnet-5`**, единственный работающий слот.
  `mercury-3` не резолвится (уходит в OpenRouter nemotron) — не использовать.
- `EMBED_BASE_URL` — по умолчанию `http://127.0.0.1:8081`.
- `RERANK_BASE_URL` — по умолчанию `http://127.0.0.1:8082`.

Владелец NexusLink — M.E.R.C.; доступ и ключи выдаёт он, в код не вшиваются.

## Формат вызова

`POST {NEXUS_LINK_BASE_URL}/chat/completions`, `Authorization: Bearer <токен>`.

**Ловушка:** при `max_tokens` меньше нужного ответ приходит только блоком
`thinking` без `text` (`stop_reason: "max_tokens"`). Для ответов давать
`max_tokens ≥ 1024` и проверять наличие непустого `content`.

**Слот ≠ модель.** В ответе есть поля `model` (реальный апстрим) и `provider`.
Именно их писать в журнал для воспроизводимости — слот может указывать на
разные апстримы в разных запросах.

## Эмбеддинги и реранкер

| Роль | Модель | Порт | Устройство | Лицензия |
|---|---|---|---|---|
| Embedding | bge-m3 (dim 1024) | 8081 | CPU | Apache-2.0 |
| Reranker | bge-reranker-base (20 мс/док) | 8082 | CPU | Apache-2.0 |

Запуск: `scripts/start-embed.ps1`, `scripts/start-rerank.ps1`.
Проверка: `curl http://127.0.0.1:8081/health` → `{"status":"ok","model":"bge-m3","dim":1024,"device":"cpu","ready":true}`.

Оба на CPU — потому что GPU (RTX 3050, 8 ГБ) занят другим, и потому что
на нашем объёме текста CPU хватает. VRAM не тратится.

## Чего НЕТ

| Компонент | Статус | Почему |
|---|---|---|
| Локальная LLM (Qwen3-8B и любая другая) | **не поднимается** | решение владельца; на sage-pl нет GPU и весов (подтверждено MERC) |
| Векторная БД (Qdrant/Chroma) | не нужна | корпус мал, индекс в памяти |
| GPU-инференс эмбеддингов | не нужен | CPU держит нагрузку |

## Итог (Q9)

В описании продукта: **LLM — NexusLink на сервере команды (sage-pl), слот
`claude-sonnet-5`; эмбеддинги и реранк — локальные модели bge-m3 и
bge-reranker-base**. Стоимость запроса — ноль. Локальная LLM не заявляется,
потому что её нет.
